# 维护规范

本页把仓库根目录 `AGENTS.md` 的 schema 展开为可执行流程。任何新增资料、知识页或批量改写都应先读本页和 [[90_来源与维护/来源总表]]。

## 三层结构

1. **原始资料层**：桌面 `C:\Users\3286\Desktop\BOOK` 中的 PDF 是来源真相，只读，不修改、不覆盖。
2. **编译知识层**：仓库中的章节页、概念页、框架页、诊断页、模板和学习页，由 LLM 维护、用户纠偏。
3. **维护规则层**：`AGENTS.md`、本页、[[index]]、[[log]] 和来源档案，规定如何摄取、引用、查询与巡检。

## 页面类型

| `type` | 用途 | 最低结构 |
|---|---|---|
| `hub` | 领域入口 | 核心问题、章节地图、工具、指标、来源 |
| `framework` | 可复用模型 | 定义、适用条件、输入、输出、步骤、边界 |
| `chapter` | 原书一章 | 本章主线、模型、指标、误区、连接、页码 |
| `concept` | 跨章节概念 | 定义、机制、使用方法、边界、相关页面 |
| `diagnostic` | 问题清单或评分 | 触发条件、问题、证据、评分、行动 |
| `template` | 可直接使用的结构 | 使用时机、字段、填写示例、决策规则 |
| `learning` | 学习与复盘 | 目标、材料、练习、验收标准 |
| `source` | 来源元数据与证据 | 路径、哈希、页数、页码偏移、章节映射、证据边界 |

## Frontmatter 基线

```yaml
---

```

允许的 `domain`：`foundation`、`procurement`、`planning`、`operations`、`leadership`、`diagnostic`、`learning`、`source`。索引和首页可使用专门的 `type`，但仍应带 `domain`、`status`、`updated`。

## 新增来源流程

1. 查 [[90_来源与维护/来源总表]]，确认是否已有同一路径、同名或同哈希来源。
2. 记录原文件名、绝对路径、字节数、SHA-256、页数、页码偏移和可提取性。
3. 扫描件先渲染与 OCR；保存逐页结果，并记录可能错识的范围。
4. 建立独立来源页；新版本建立新页，旧页保留。
5. 先写章节摘要，再更新跨章节概念、框架和诊断。
6. 更新相关 MOC、[[index]]、[[log]]。
7. 运行 `node 90_来源与维护/工具/kb-audit.mjs`，修复断链、孤立页和元数据问题。

## 引用规则

- 原书引用：`原书第 X-Y 页；PDF 第 X+16-Y+16 页`。
- 章节页在“来源”节链接对应来源档案。
- 综合判断、诊断问题、评分和模板标注为“知识库再创作”。
- OCR 底稿用于定位，不代替 PDF 原文；精确引文须回看原页。
- 外部资料与旧结论冲突时，在相关页增加“冲突与待核验”，并列双方证据。

## 查询与回写流程

1. 从 [[index]] 和领域 MOC 找候选页。
2. 读知识页；涉及事实、定义、页码时查来源档案或 OCR 全文。
3. 回答中区分“原书观点”“跨来源综合”“实践建议”。
4. 如果形成新的决策树、比较表、诊断或案例复盘，经用户确认后回写。
5. 在 [[log]] 记录重要查询和回写。

## 巡检质量门

- 所有 wikilink 可解析，没有意外断链。
- 除总入口外，每页至少有 1 个上游 Hub/框架链接和 2 个相关页链接。
- 每页 frontmatter 有合法 `type`、`domain`、`status`、`updated`。
- 章节页的 `source_pages` 与来源档案一致。
- 同一指标只有一种主定义；别名必须明确。
- “原书观点”和“知识库综合”没有混写。
- Mermaid 图块闭合，标题层级不跳级。
- 新页加入 [[index]]；结构性变更写入 [[log]]。

## 删除与归档

- 不删除桌面原始 PDF。
- 临时渲染图在全文底稿与 OCR JSON 校验完成后可删除。
- 被替代的知识页优先移动到归档并在 [[log]] 记录，不静默删除。
- `这是我们的第一篇笔记.md` 是用户初始文件，除非用户明确要求，否则保留。
