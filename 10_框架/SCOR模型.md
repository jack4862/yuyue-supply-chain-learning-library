# SCOR 模型

SCOR（Supply Chain Operations Reference）是供应链流程参考框架。SCMP 教材在组织设计和绩效章节中使用其流程与指标语言。

## 一级流程

| 流程 | 解决的问题 |
|---|---|
| Plan 计划 | 如何平衡需求、供应、资源和业务规则？ |
| Source 采购 | 如何获取物料、服务与供应能力？ |
| Make 生产 | 如何转换投入并形成合格产出？ |
| Deliver 交付 | 如何履行订单、配送并提供服务？ |
| Return 退货 | 如何接收并处理退回产品？ |
| Enable 使能 | 如何提供数据、人力、技术、合同、绩效和治理支持？ |

## 五类一级绩效

1. **可靠性 Reliability**：是否按承诺完成，例如完美订单满足率。
2. **响应性 Responsiveness**：多快满足需求，例如订单履行周期。
3. **敏捷性 Agility**：面对外部变化多快调整，例如上调/下调灵活性。
4. **成本 Cost**：端到端供应链总成本。
5. **资产管理 Asset Management Efficiency**：库存、现金和固定资产效率。

SCMP《供应链领导力》还使用“供应链总风险”作为补充目标。风险不应只放在事后控制，而应与可靠性、响应、成本和资产效率一起进入目标体系。

## 使用时的三个层次

### 1. 流程配置

确认企业采用哪些 SCOR 一级和二级流程，哪些活动属于供应商、企业、渠道商或客户。

### 2. 绩效分解

把一级指标向下分解为流程指标和岗位指标。例如：

- 完美订单满足率 → 齐套率、订单准确率、按时交付率、文档准确率；
- 订单履行周期 → 需求确认、采购、生产、检验、仓储、运输周期；
- 供应链总成本 → 采购、制造、库存、仓储、运输、质量和服务成本。

### 3. 标杆比较

SCOR 的价值不在于给企业强行套模板，而在于用共同语言描述流程与绩效，支持内部比较和跨企业对标。

## 常见误区

- 只做流程建模，不把指标与责任绑定；
- 只追求成本与资产效率，忽略可靠性和风险；
- 指标跨层级口径不一致；
- 认为 SCOR 是软件或必须一次性全覆盖的认证项目。
